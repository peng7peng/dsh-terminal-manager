## 一、总体思路

把 better-sidebar 的**前端组件代码**（多 Tab 管理、文件树、CodeMirror 编辑器）抄到我们自己的 dsh-terminal-manager 插件里，和现有的远程终端能力（SSH/Telnet 多会话、广播）整合成**一个完整的终端工作台**。

**用户只装一个插件**，得到：

| 能力 | 来源 |
|---|---|
| 远程终端（SSH/Telnet 多会话、同屏、广播） | 现有 MVP |
| 本地文件查看 / 编辑（CodeMirror） | 抄 better-sidebar |
| 本地文件树 | 抄 better-sidebar |
| 文件上传 / 下载（SSH + Telnet） | 新开发 |
| 多行选中发送 | 新开发 |
| TC 语法兼容 | 新开发（等样例） |
| 日志管理 / 共享端口 | 扩展模块负责人开发（本方案预留接口） |

**不引入 better-sidebar 插件本身**，不依赖它的安装。

### 2.1 布局总览：DSH 页面内嵌不动 + 浮动编辑器 + 文件面板叠加

**插件不改变 DSH 页面骨架**（侧栏 | AI 聊天区 | 覆盖层工作区），新增能力以**叠加**方式进入：

```
┌──────────┬──────────────────┬─────────────────────────────────┐
│ DSH 侧栏  │   AI 聊天区       │  覆盖层工作区（插件，现有形态）     │
│ (现状)    │   (DSH 的，不动)  │ ┌───────────────────┬─────────┐ │
│ 💬会话    │  用户/AI 消息     │ │ 终端网格 (MVP 原样) │ 连接面板 │ │
│ 🖥️终端管理│  Agent 工具卡片   │ ├───────────────────┤ (MVP原样)│ │
│          │                  │ │ 📢 广播栏（MVP 原样）│         │ │
│          │  [输入框]         │ ├───────────────────┴─────────┤ │
│          │                  │ │ ▶ 💻 远端文件 [终端][路径]     │ │
│          │                  │ │ ▶ 📁 本地文件 [当前根]         │ │
└──────────┴──────────────────┴─┴─────────────────────────────┴─┘
    ↑ 浮动编辑器（fixed 于整个视口，可拖到 AI 聊天区上方）
```

**核心设计决策**：
- **终端网格、连接面板、广播栏、工作区头部 = MVP 原样保留，零迁移**
- **文件面板 ×2**（远端/本地）：**收起条**常驻广播栏下方（各一行高，不占空间），点击**展开为面板**（非浮动窗口，出现在广播栏下方，终端网格自动压缩）；展开后可收回
- **编辑器**：**浮动窗口**（fixed 于整个视口，z-index 60~90 安全区），可拖动/缩放/最大化/最小化成底部标签，**可拖到 AI 聊天区上方**
- Agent 调 `tm_*` 工具时终端同步显示（人机共视，MVP 已有）

### 2.4 编辑器设计（浮动窗口，抄 better-sidebar）

- **形态**：独立浮动窗（可拖动/右下角缩放/最大化/最小化成底部标签），**一个浮动窗、内部多 Tab**（避免窗满为患）；Tab 带未保存圆点
- **内核**：CodeMirror 6（better-sidebar 同款，全量打包，见 2.7）
- **支持类型**：`.sh` / `.py` / `.txt` / `.csv` / `.md` / `.json` / `.ini`，其余纯文本。TC 脚本即 `.txt`（不做内容感知，执行/发送由用户点按钮决定）；**`.xlsx` 待定**（代价见 3.9，本期默认不支持）
- **功能**：Ctrl/Cmd+S 保存、**语法高亮（已确认做）**、**脏标记（已确认做）**、底部操作栏（**双按钮常驻**：[▶ 执行脚本] + [▶ 发送选中→]，见 2.5）
- **不做**：Git 集成、Mermaid、>10MB 大文件（提示只读打开）

### 2.5 关键交互流程（原型已验证）

**流程 A：TC 脚本执行**（模块一，入口 = 编辑器）

```
打开 TC 脚本（`case1.txt`，内容含 `N:`/`*:` 语法行）→ 点 **[▶ 执行脚本]**（底部双按钮常驻，用户自选）
  → 点击 → 按脚本端口映射逐条发送：*: → 已标注 TC 编号的在线终端；0:/1: → 对应终端
  → 命令逐条"打"进对应终端窗格（人机共视，与手动敲完全一致）
  → 编辑器底部滑出汇总条：逐端口 ✓/✗（超时标 waitReason=timeout 可复查）
  → 全程不弹终端选择（脚本内已写好映射）
```

**选中执行**：TC 脚本内选中若干行 → **右键「▶ 执行选中脚本」** → 只执行选中行（同样打终端 + 汇总）。

**流程 B：选中发送**（模块五，入口 = 编辑器，非脚本文件）

```
打开 .md/.csv → 选中内容 → 底部 [▶ 发送选中 →]（或右键「发送选中到终端…」）
  → 弹出终端多选弹窗（在线终端复选框，实时显示 发送(N)，0 个禁用）
  → 确认 → 逐条发送：每条等回显/静默（复用 sendAndWait），超时提示可跳过
  → 命令出现在勾选终端窗格 + toast 汇总
```

**区分原则（已确认，方案 A）**：**按钮语义区分（双按钮常驻）**——[▶ 执行脚本] 按映射走、不选终端；[▶ 发送选中→] 要选终端。**广播栏永远只管手动命令**，两边语义不混。

**流程 C：文件上传 / 下载**（模块三，【排期最后 + 后端归属待定，见 3.2；面板 UI 已确认】）

```
浏览：远端文件面板直接浏览（切终端 / 上一级 / 面包屑跳转 / 刷新）
上传：本地面板选中 → 远端面板 [📤 上传文件 / 📁 上传文件夹] → SFTP → 进度条
下载：远端面板选中 → [📥 下载文件 / 🗂️ 下载文件夹] → SFTP → 浏览器保存
编辑器 [📤 上传]：当前编辑文件上传（弹目标设备多选）
Telnet：命令模拟（base64 + cat），≤1MB，UI 标注「实验性」，配置可关
⚠ 传输后端归属待定（可能扩展模块负责人做公共后端）；面板 UI 与交互已定（file-panels.html）
```

**流程 D：Agent 联动**（现有 + 待定工具）

```
AI 聊天区：Agent 调 tm_connect/tm_send（现有）→ 终端窗格同步显示（人机共视）
tm_upload/tm_download（文件上传下载的 AI 路径）随模块三
```

### 2.6 连接面板【改定：保留现状，不搬家】

维持 MVP 现状（右侧常驻），表单**不新增 TC 字段**——TC 编号纯动态（在线会话列表顺序，【暂定】），编号徽章实时显示在「活跃会话」列表项上。原"移到底部抽屉"方案**废弃**。

### 2.7 构建与产物（chunk 策略）【已确认：方案 B，先全量】

**决策：不做 chunk 基建，CodeMirror 全量打进 client.js**：
- client.js 预计 745KB → ~2MB；内网百兆下载 <1 秒，用户感知几乎为零
- 省 1 天 chunk 基建工作量；首次打开编辑器无额外延迟
- 已知取舍：后续若模块继续膨胀出现加载慢的反馈，再引入 chunk 基建（抄 better-sidebar 的 `__dshChunks__` 懒加载机制，方案留档可随时启用）
- CodeMirror CSS 走现有虚拟模块机制（`tm:codemirror-css`，同 `tm:xterm-css`）

### 3.2 模块三：文件上传 / 下载（排期最后；后端归属待定，方案先行）

> **归属待定**：后端可能由扩展模块负责人开发（日志上传下载复用同一后端）、本插件做 UI 接入；也可能本插件自研、扩展模块负责人复用。**方案本身不依赖归属**——以下为完整技术方案，归属定后按此直接开工。

#### 3.2.1 架构：公共文件服务层

```
消费方（编辑器上传按钮 / 文件树拖拽 / tm_upload / 扩展模块负责人日志模块）
        ↓
file-service.ts（公共门面：本地 + 远程统一 API）
  ├── 本地：readLocal / writeLocal / listLocal（限树根，复用 files.read/write/tree 路由）
  └── 远程：upload / download / list（按会话协议分派）
        ├── SSH 会话 → transport/sftp.ts（ssh2 sftp 通道）
        └── Telnet 会话 → 命令模拟（base64 + cat，实验性）
```

#### 3.2.2 SFTP 传输层（`transport/sftp.ts`）

| 项 | 设计 |
|---|---|
| 连接复用 | **复用现有 SSH 会话的 `Client` 连接新开 sftp channel**（一次认证多通道），不新建 TCP——改造点：`transport/ssh.ts` 保存 Client 引用并导出 `getSftp()` |
| API | `put(local, remote, onProgress)` / `get(remote, local, onProgress)` / `list(remote)`（远程文件树用） |
| 进度 | `fastPut/fastGet` 的 step 回调节流（200ms）→ WS `file-progress` 帧 |
| 生命周期 | 懒建立（首次文件操作时）；会话断开时销毁；传输中会话置 busy（防手动键入穿插） |
| 失败处理 | 传输中断清理远端半成品文件；错误映射 `REMOTE_IO` |

#### 3.2.3 Telnet 命令模拟（实验性）

| 项 | 设计 |
|---|---|
| 上传 | 本地读文件 → base64 → **分块**（每块 ~64KB 避免命令行过长）→ `printf '%s' '<块>' >> /tmp/.tm_b64` → `base64 -d /tmp/.tm_b64 > 目标路径` → `md5sum` 校验（可选） |
| 下载 | `base64 <path>` 读回解码；输出超环形缓冲（1MiB）则分块读取或标「文件过大，仅 SSH 支持」 |
| 限制 | 单文件 ≤ 1MB（base64 膨胀 33%）；依赖目标 shell 有 base64（BusyBox 一般有）；UI 标「实验性」、Config 开关可关 |
| 隔离 | 模拟传输期间会话 busy，手动键入排队 |

#### 3.2.4 路由与帧

| 路由/帧 | 方法 | 说明 |
|---|---|---|
| `/term-manager/files/upload` | POST | raw body + query（sessionId/remotePath）→ file-service.upload；围栏：loopback + 会话存在 + remotePath 规范化 |
| `/term-manager/files/download` | GET | sessionId/remotePath → file-service.download → 流式响应（content-disposition 触发浏览器保存） |
| `/term-io` 帧 `{kind:'file-progress'}` | 下行 | op/sessionId/remotePath/percent |

#### 3.2.5 前端 UI（已确认设计，见 2.3 / file-panels.html）

- **远端文件面板**（收起条/展开）：切终端、上一级、面包屑、列表；按钮 = 上传文件/下载文件/上传文件夹/下载文件夹/刷新
- **本地文件面板**：同款工具栏；双击文件 → 编辑器打开；上传/下载与远端面板联动（本地选中 → 远端当前目录）
- 编辑器 [📤 上传]：当前编辑文件 → 弹目标设备多选 → 进度条
- 进度：toast + WS 帧驱动进度条

#### 3.2.6 AI 工具（通用，人工 + AI 双路径）

| 工具 | 参数 | 行为 |
|---|---|---|
| `tm_upload` | `{sessionId, localPath, remotePath}` | localPath 限树根内；AI 路径过命令守卫（`guard:{}`）；返回 `{ok, bytes, durationMs}` |
| `tm_download` | `{sessionId, remotePath, localPath?}` | 无 localPath → 返回浏览器下载 URL；有 → 存树根内 |

错误码：`SESSION_NOT_FOUND` / `DISCONNECTED` / `FILE_TOO_LARGE` / `REMOTE_IO` / `VALIDATION`。presentCall 卡片显示文件名+大小+方向。

- 测试：mock SSH 服务器测 put/get/list/进度（复用 `mock-ssh-device` 思路）；`mock-device` 加 base64 命令测 Telnet 往返；file-service 本地树根逃逸拒绝；`tm_*` 端到端

### 3.4 模块一：TC 语法兼容（交互已定；映射方式【暂定】待用户确认）

- **语法（按原型设想，待样例校正）**：`*:命令` = 全部参与终端执行；`N:命令` = TC 编号 N 的终端；`**` 行 = 注释
- **端口映射【暂定：纯动态，待用户确认】**：**TC 编号 = 活跃会话列表顺序**（在线会话，第 1 个 = TC0，第 2 个 = TC1…）；**拖动排序即切换编号**（复用现有 `sessionOrder`/`onReorder`，MVP 已实现拖动）；**不落盘、后端无 TC 状态**。待与用户确认编号语义是「窗口顺序」还是「物理端口」——若为后者则回退到「连接配置标注 tcPort」方案
  - 边界规则：断线（closed）会话不占编号；隐藏窗格占用编号；编号无对应在线终端 → 汇总条标 ✗「无对应终端」
  - 防误执行：**执行前弹映射确认框**（TC0→dut-ssh-22，TC1→dut-ssh-2222…，确认后才发）
- **实现分工**：TC 编号 → sessionId 的翻译在**前端**（从 `sortedSessions` 实时算）；执行 RPC 传 `assignments: [{sessionId, command}]`——**后端不需要知道 TC 概念**，只管逐条发送（复用 `sendAndWait`）
- **解析器**：`src/tc-parser.ts` 纯函数（脚本文本 → `{tcPort: number|'*', command, isComment}[]`），样例到位后只改此文件
- **执行入口**：编辑器 [▶ 执行脚本]（整脚本）/ 右键「执行选中脚本」（选中行）→ 映射确认框 → 逐条发送打终端窗格（人机共视）+ 编辑器底部汇总条（逐端口 ✓/✗，超时可复查）
- **降级**：样例语法差异过大 → 降级为「选中发送 + 手动选终端」

### 3.5 预留给扩展模块负责人的接口

```ts
// src/types/events.ts —— 唯一的模块间契约，两人共同维护
export type TmEvent =
  | { type: 'output'; sessionId: string; data: string; ts: number }
  | { type: 'input';   sessionId: string; data: string; ts: number }
  | { type: 'status';  sessionId: string; status: 'connecting'|'open'|'closed'|'removed'; ts: number }
  | { type: 'file';    sessionId?: string; op: 'upload'|'download'; path: string; ok: boolean; ts: number }

export interface TmEventBus {
  emit(e: TmEvent): void
  on(h: (e: TmEvent) => void): () => void   // 返回取消订阅
}
```

- 我（主线负责人）在 SessionManager / 终端交互里埋 `emit` 点
- 扩展模块负责人的日志模块只 `on`，不反向依赖终端代码
- 共享端口（模块六）如需控制会话，走现有 `SessionManager` 公开方法，不绕过
- **文件服务后端归属待定（见 3.2）**：若扩展模块负责人做公共后端，接口规范追加「文件服务 API」契约（本地读写 + SFTP 远程传输的统一入口）；若本插件自研，扩展模块负责人的日志落盘/下载复用本插件的 `files.read`/`files.write` 路由。**下次对齐会必谈此项**

### 3.6 本地文件边界【已确认】

**问题**：better-sidebar 的文件工作台是 **per-session**（每个 DSH 会话有自己的 cwd，`fs.tree` 按会话隔离）；我们的 terminal-manager 是**公共会话池**（跨会话），两者模型不同。

**决策：文件树本地根 = 配置默认值 + 用户可切换**：

| 项 | 设计 |
|---|---|
| 默认根 | Config schema 配置项 `workspaceRoot`，**默认 = DSH 进程 cwd** |
| 切换根 | 文件树「📂 换目录…」弹出目录选择 → 以新目录为根；localStorage 记忆最近选择（刷新/重启保留） |
| 会话关系 | 所有会话共享同一个文件树（与公共会话池定位一致）；切换终端不影响文件树 |
| 边界约束 | 文件读写**严格限定在当前树根内**（路径归一化 + 符号链接解析后校验，抄 better-sidebar 的 `path-security.ts`），越界拒绝；切换根 = 用户主动授权该目录 |
| 文档明示 | 「文件访问范围 = 文件树当前根目录」写进 README |

### 3.7 安全与路由

新增路由统一挂 **`/term-manager` 现有前缀**下（复用 CORS/OPTIONS 处理），信任围栏沿用现有模型（`/term-io` 的 loopback 栅栏 + webServer 本机绑定）：

| 路由 | 方法 | 用途 | 围栏 |
|---|---|---|---|
| `/term-manager/files/tree` | POST | 本地目录树（懒加载，支持列任意目录供「换目录」选择） | 限当前树根内读写；列目录仅读 |
| `/term-manager/files/read` | POST | 读本地文件（编辑器打开；日志模块可复用作下载源） | 当前树根限定 |
| `/term-manager/files/write` | POST | 写本地文件（Ctrl+S 保存，原子写；日志模块可复用作落盘） | 当前树根限定 |
| `/term-manager/files/upload` | POST | 浏览器 → host 半（raw body + query 传路径）→ SFTP 转发到设备 | 【待定，随模块三】 |
| `/term-manager/files/download` | GET | 设备 → host 半（SFTP 读）→ 流式回浏览器 | 【待定，随模块三】 |
| 进度帧 | `/term-io` WS | `kind: 'file-progress'` 下行帧（sessionId/op/percent） | 【待定，随模块三】 |

## 六、风险与开放问题

1. **文件服务后端归属未定（本周必须对齐）**：文件上传/下载的后端可能由扩展模块负责人开发（日志上传下载复用同一后端）、本插件只做 UI；也可能本插件自研、扩展模块负责人复用。**方案已完整（3.2），归属只影响谁做**——EventBus 对齐会（本周）必须谈定，并把结论写进接口规范。
2. **Telnet 文件传输可靠性**：命令模拟方案受目标 shell 限制（无 base64 的设备失败）——UI 标注「实验性」，配置可关。
3. **本地文件边界**：文件访问范围 = 文件树当前根（默认 workspaceRoot，用户可切换；已定案，见 3.6）。
4. **TC 映射方式暂定**：纯动态（会话列表顺序）待用户确认语义（窗口顺序 vs 物理端口）——若为物理端口语义回退 tcPort 固定标注；执行前映射确认框兜底防误执行。
5. **TC 语法样例**：本期最大不确定项。解析器按原型设想语法先实现（纯函数易替换），真实样例到位后校正；差异过大则降级为「选中发送 + 手动选终端」。
6. **client.js 体积**：CodeMirror + 5 语言包全量打包后 ~2.2MB——内网可接受（已知取舍，见 2.7）；若后续反馈加载慢，再启用 chunk 基建（方案留档）。
7. **DSH 版本基线差异**：better-sidebar 面向 DSH 0.1.2-alpha.x（peer `^0.1.2-alpha.2`），我们的插件基线是 0.1.1-rc.2 时代。它用的部分 API（`ctx.modules`、`dsh-client-locale` 等）在我们的基线里可能不存在——抄代码时**逐文件核对 API 可用性**，遇到不存在的降级实现。这正是选择「抄代码」而非「安装依赖」的原因之一。
8. **与扩展模块负责人的合并节奏**：EventBus 契约文件（`src/types/events.ts`）先合入 main，两人各自分支开发，每周对齐一次接口变更；文件服务归属结论同步写入。
