## 〇、演示前 30 分钟 —— 环境准备

### 0.1 确认真实设备就绪

目标设备 `7.218.30.25` 已配置好以下端口，都处于监听状态：

| 端口 | 协议 | 说明 |
|------|------|------|
| 22 | SSH | 标准 SSH |
| 23 | Telnet | Telnet 登录 |
| 2222 | SSH | 备用 SSH |
| 2223 | SSH | 备用 SSH |
| 2323 | SSH | 备用 SSH |
| 2324 | SSH | 备用 SSH |

> 无需启动模拟设备，全部使用真实 SSH/Telnet 服务。

### 0.2 启动 DSH

打开一个终端：

```bash
cd D:/myProject/dsh/deepseek-harness
pnpm dsh --profile tm-dev --port 4580 --no-open
```

**看到什么**：输出里出现 `listening on http://...:4580`。不要关。

### 0.3 打开浏览器

1. 打开 Chrome / Edge，地址栏：`http://127.0.0.1:4580`
2. **硬刷新**：按 `Ctrl + F5`（确保加载最新 client.js）
3. **检查插件加载成功**：按 `F12` → Console，没有红色报错；Network 里 `/plugins/dsh-terminal-manager/client.js` 状态码 200

### 0.4 准备本地脚本文件

在任意目录（比如 `D:/demo/test-plan.md`）新建一个文件，内容：

```markdown
请逐条执行并汇报：

- [ ] 执行 `hostname`，确认设备主机名
- [ ] 执行 `date`，确认系统时间是否准确
- [ ] 执行 `who`，确认当前登录用户
- [ ] 执行 `df -h`，确认磁盘使用情况
- [ ] 执行 `free -m`，确认内存使用情况
- [ ] 执行 `cat /proc/cpuinfo | grep "model name" | head -1`，确认 CPU 型号
- [ ] 执行 `ping -c 3 8.8.8.8`，确认网络连通性
- [ ] 执行 `show version`，确认固件版本
```

> 💡 **为什么**：第三幕"Agent 读本地文件"要用。如果 DSH 启动的 cwd 不在 `D:/demo`，就把文件放到 DSH cwd 下。

### 0.5 检查清单

演示前 2 分钟再过一遍：

- [ ] 目标设备 `7.218.30.25` 的 22/23/2222/2223/2323/2324 端口可连（任意选一个 SSH 端口确认）
- [ ] DSH 在跑（4580 端口）
- [ ] 浏览器 `http://127.0.0.1:4580` 能打开，侧边栏最底部有 **「🖥️ 终端管理」** 按钮
- [ ] 本地 `test-plan.md` 文件就位

## 一、第一幕：连接环境（单机 Telnet）—— 3 分钟

### 步骤 1.1 打开终端工作区

| 动作 | 预期结果 |
|---|---|
| 点左侧 DSH 侧边栏最底部的 **「🖥️ 终端管理」** 按钮 | 屏幕右侧滑出「终端管理」工作区覆盖层；聊天区变窄，终端区占右半屏；按钮变蓝（激活态） |

**解说词**：「这就是我们做的 DSH 插件——装上就有，不引入额外中间件。工作区跟聊天区并排，后续 Agent 操作时这里同步显示。」

### 步骤 1.2 创建第一条 Telnet 连接

工作区右侧是「连接面板」。

| 动作 | 预期结果 |
|---|---|
| 在连接面板顶部，协议下拉选 **「Telnet」** | 表单字段变化：用户名/密码/密钥字段隐藏（Telnet 不强制） |
| **名称** 填：`dut-telnet` | 字段变红不算错（空校验），填完红框消失 |
| **主机** 填：`7.218.30.25` | — |
| **端口** 填：`23` | — |
| 点 **「保存」** 按钮 | 下方「⭐ 收藏」区域出现 `dut-telnet` 卡片；表单清空回到默认 |

**解说词**：「保存的连接会持久化到本地 JSON 文件，下次打开还能用。」

### 步骤 1.3 以 Telnet 连接设备

| 动作 | 预期结果 |
|---|---|
| 在「⭐ 收藏」里 **点一下 `dut-telnet` 卡片** | 表单回填 dut-telnet 的信息 |
| 点 **「连接」** 按钮（不是「保存」） | 顶部「🖥️ 终端」标题旁的「在线 0/0」变成 **「在线 1/1」**；左侧终端网格出现一个窗格，显示设备的 Telnet 登录界面 |

**解说词**：「这就是设备的登录界面，和 Putty 看到的一样。但注意——这个会话现在是共享的，Agent 也能接着用。」

### 步骤 1.4 人在终端里敲命令

| 动作 | 预期结果 |
|---|---|
| **点一下**左侧的终端窗格（让它获得焦点） | 终端出现光标 |
| 键盘敲：`show version` 然后 **回车** | 终端回显命令本身 + 设备的实际输出（如 Linux 版 `show` 命令的结果），然后再次出现提示符 |

**解说词**：「人直连设备敲命令，跟平时一样。」

## 二、第二幕：多端口同屏 + 广播 —— 5 分钟

### 步骤 2.1 连接更多设备（SSH 各端口）

依次连接以下设备（演示者可只连 3-4 个，有余裕可连满 6 个）：

| 次数 | 协议 | 名称 | 主机 | 端口 |
|------|------|------|------|------|
| 第 1 次 | SSH | `dut-ssh-22` | 7.218.30.25 | 22 |
| 第 2 次 | SSH | `dut-ssh-2222` | 7.218.30.25 | 2222 |
| 第 3 次 | SSH | `dut-ssh-2223` | 7.218.30.25 | 2223 |
| 第 4 次 | SSH | `dut-ssh-2323` | 7.218.30.25 | 2323 |
| 第 5 次 | SSH | `dut-ssh-2324` | 7.218.30.25 | 2324 |

> **注意**：由于这些端口 SSH 到同一台设备，每连一个都会要求输入密码。可以提前告知演示助手或在演示前批量建立连接以节省时间。

**预期结果**：每次连接后「在线 X/Y」递增，终端网格自动扩展（多窗格并排或网格布局）。

**解说词**：「这台设备开了 6 个端口，现在我们在同一个终端工作区里同时管着多个会话。芯片验证团队日常对着 4 台板子，这里可以切到 3 列（顶部「列数」下拉）。」

### 步骤 2.2 演示响应式布局（可选，30 秒）

| 动作 | 预期结果 |
|---|---|
| 鼠标放到聊天和终端之间的**竖条分隔条**上（光标变成 ↔） | 光标变化提示可拖 |
| 向左拖 | 聊天变窄、终端变宽 |
| 向右拖 | 聊天变宽、终端变窄 |
| 顶部「列数」下拉切到 **1 列** | 终端变上下叠放 |
| 切回 **2 列**（或 3 列） | 恢复多列布局 |

### 步骤 2.3 广播命令到全部

| 动作 | 预期结果 |
|---|---|
| 视线往下，找到终端区底部的**广播栏**（两行布局） | 第一行是目标选择 chips（「全部」+ 每台设备的 chip），第二行是输入框 + 发送按钮 |
| 第一行的 **「全部」chip** 应该是亮的（默认全选） | — |
| 第二行的输入框里敲：`show version` | — |
| 点 **「发送」** 按钮（或按回车） | **所有终端同时**回显命令 + 设备的实际输出 |

**解说词**：「一条命令，所有会话同时执行。以前工程师开 4 个 Putty 窗口复制粘贴，现在一条广播搞定。」

### 步骤 2.4 广播到部分

| 动作 | 预期结果 |
|---|---|
| 在广播栏第一行，**点一下 `dut-ssh-22` 的 chip**（取消选中，只剩其他亮） | chip 变暗 |
| 输入框敲：`hostname` 然后发送 | **只有被选中的窗格**回显命令和执行结果；dut-ssh-22 无变化 |

**解说词**：「想只对某几台操作时，取消勾选其他就行。」

## 三、第三幕：Agent 闭环 —— 10 分钟 ⭐ 核心

### 步骤 3.1 切回聊天区

| 动作 | 预期结果 |
|---|---|
| 鼠标点到左侧**聊天输入框**（DSH 的主对话区） | 输入框获焦，可以打字 |

**解说词**：「现在开始展示核心价值——让 Agent 来操作环境。」

### 步骤 3.2 Agent 单机任务（读本地 + 操作设备）

| 动作 | 预期结果 |
|---|---|
| 聊天输入框敲：`读一下当前目录的 test-plan.md，按照里面的验证清单对 7.218.30.25:22 这台设备执行` | DSH 开始思考 |
| **观察**：Agent 的回复 + 工具调用过程 | Agent 依次：①读本地 `test-plan.md`（工具调用可见）；②调 `tm_connect` 连设备（或复用已开的 dut-ssh-22）；③调 `tm_send` 跑 `show version`；④调 `tm_send` 跑 `hostname`；⑤调 `tm_send` 跑 `df -h`；⑥汇总报告 |
| **同时观察**：右侧终端工作区 | Agent 连的会话对应的终端窗格里，能看到命令在被执行（人机共视） |
| Agent 回复出来 | 结构化报告：每条验证项 ✅/❌ |

**解说词**（在 Agent 跑的时候说）：「注意看右侧终端——Agent 在操作设备时，终端同步显示，不是黑盒。左边是 Agent 的分析，右边是设备的真实响应，两相对照。」

**如果 Agent 没调工具**：追加提示「请用 dsh-terminal-manager 提供的工具来操作设备」。


### 步骤 3.3 Agent 读现场（"看"屏幕）

| 动作 | 预期结果 |
|---|---|
| 聊天输入框敲：`连上 7.218.30.25:22，告诉我当前屏幕上显示什么？设备什么状态？` | DSH 思考 |
| Agent 行为 | 调 `tm_read` 读当前环形缓冲 |
| Agent 回复 | 描述当前提示符状态（如 `root@hostname:~#`）、最近执行的命令等 |

**解说词**：「Agent 不只是发命令，它也能'看'屏幕。可以帮你确认设备是不是卡在某个状态、有没有异常输出。比如你可以问'设备当前是不是在加载中'。」
