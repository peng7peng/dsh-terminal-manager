## 〇、演示前 30 分钟 —— 环境准备

### 0.1 启动两个模拟设备

打开 **两个** Git Bash / 终端窗口，分别跑：

```bash
# 窗口 A
cd D:/myProject/dsh/dsh-terminal-manager
node scripts/mock-device.mjs 2323
```

```bash
# 窗口 B
cd D:/myProject/dsh/dsh-terminal-manager
node scripts/mock-device.mjs 2324
```

**看到什么**：终端打印 `Mock Router listening on :2323`（/`:2324`）。不要关这两个窗口，整个演示期间它们都要跑着。

### 0.2 启动 DSH

再开一个终端：

```bash
cd D:/myProject/dsh/deepseek-harness
pnpm dsh --profile tm-dev --port 4580 --no-open
```

**看到什么**：输出里出现 `listening on http://...:4580`。不要关。

### 0.3 打开浏览器

1. 打开 Chrome / Edge，地址栏：`http://127.0.0.1:4580`
2. **硬刷新**：按 `Ctrl + F5`（确保加载最新 client.js）
3. **检查插件加载成功**：按 `F12` → Console，没有红色报错；Network 里 `/plugins/dsh-terminal-manager/client.js` 状态码 200

### 0.4 准备本地脚本文件

在任意目录（比如 `D:/demo/test-plan.md`）新建一个文件，内容：

```markdown
# DUT 验证清单

请逐条执行并汇报：
- [ ] 执行 `show version`，确认固件版本是 MockOS 1.0
- [ ] 执行 `show ip interface brief`，确认接口状态
- [ ] 执行 `ping 8.8.8.8`，确认连通性
```

> 💡 **为什么**：第三幕"Agent 读本地文件"要用。如果 DSH 启动的 cwd 不在 `D:/demo`，就把文件放到 DSH cwd 下。

### 0.5 检查清单

演示前 2 分钟再过一遍：

- [ ] 两个 mock-device 在跑（看终端输出）
- [ ] DSH 在跑（4580 端口）
- [ ] 浏览器 `http://127.0.0.1:4580` 能打开，侧边栏最底部有 **「🖥️ 终端管理」** 按钮
- [ ] 本地 `test-plan.md` 文件就位

## 一、第一幕：连接环境（单机 Telnet）—— 3 分钟

### 步骤 1.1 打开终端工作区

| 动作 | 预期结果 |
|---|---|
| 点左侧 DSH 侧边栏最底部的 **「🖥️ 终端管理」** 按钮 | 屏幕右侧滑出「终端管理」工作区覆盖层；聊天区变窄，终端区占右半屏；按钮变蓝（激活态） |

**解说词**：「这就是我们做的 DSH 插件——装上就有，不引入额外中间件。工作区跟聊天区并排，后续 Agent 操作时这里同步显示。」

### 步骤 1.2 创建第一条连接

工作区右侧是「连接面板」。

| 动作 | 预期结果 |
|---|---|
| 在连接面板顶部，协议下拉选 **「Telnet」** | 表单字段变化：用户名/密码/密钥字段隐藏（Telnet 不强制） |
| **名称** 填：`dut-1` | 字段变红不算错（空校验），填完红框消失 |
| **主机** 填：`127.0.0.1` | — |
| **端口** 填：`2323` | — |
| 点 **「保存」** 按钮 | 下方「⭐ 收藏」区域出现 `dut-1` 卡片；表单清空回到默认 |

**解说词**：「保存的连接会持久化到本地 JSON 文件，下次打开还能用。」

### 步骤 1.3 连接设备

| 动作 | 预期结果 |
|---|---|
| 在「⭐ 收藏」里 **点一下 `dut-1` 卡片** | 表单回填 dut-1 的信息 |
| 点 **「连接」** 按钮（不是「保存」） | 顶部「🖥️ 终端」标题旁的「在线 0/0」变成 **「在线 1/1」**；左侧终端网格出现一个窗格，显示青色横幅 `Mock Router :2323` + 绿色提示符 `router>` |

**解说词**：「这就是设备的登录界面，和 Putty 看到的一样。但注意——这个会话现在是共享的，Agent 也能接着用。」

### 步骤 1.4 人在终端里敲命令

| 动作 | 预期结果 |
|---|---|
| **点一下**左侧的终端窗格（让它获得焦点） | 终端出现光标 |
| 键盘敲：`show version` 然后 **回车** | 终端回显命令本身 + 输出 `MockOS Version 1.0.4`，然后再次出现 `router>` 提示符 |

**解说词**：「人直连设备敲命令，跟平时一样。」

## 二、第二幕：多端口同屏 + 广播 —— 4 分钟

### 步骤 2.1 连接第二台设备

| 动作 | 预期结果 |
|---|---|
| 右侧连接面板表单里，**名称**改填 `dut-2`，**端口**改 `2324`（其他不变） | 表单显示新值 |
| 点 **「连接」** | 「在线 1/1」变成 **「在线 2/2」**；终端网格变成 **两个窗格并排**（默认 2 列布局），左边 dut-1，右边 dut-2，都显示 `Mock Router` 横幅 |

**解说词**：「两台 DUT 同时在线、同屏显示。芯片验证团队日常对着 4 台板子，这里可以切到 3 列（顶部「列数」下拉）。」

### 步骤 2.2 演示响应式布局（可选，30 秒）

| 动作 | 预期结果 |
|---|---|
| 鼠标放到聊天和终端之间的**竖条分隔条**上（光标变成 ↔） | 光标变化提示可拖 |
| 向左拖 | 聊天变窄、终端变宽 |
| 向右拖 | 聊天变宽、终端变窄 |
| 顶部「列数」下拉切到 **1 列** | 两台终端变上下叠放 |
| 切回 **2 列** | 恢复并排 |

### 步骤 2.3 广播命令到全部

| 动作 | 预期结果 |
|---|---|
| 视线往下，找到终端区底部的**广播栏**（两行布局） | 第一行是目标选择 chips（「全部」+ 每台设备的 chip），第二行是输入框 + 发送按钮 |
| 第一行的 **「全部」chip** 应该是亮的（默认全选） | — |
| 第二行的输入框里敲：`show version` | — |
| 点 **「发送」** 按钮（或按回车） | **两台终端同时**回显命令 + `MockOS Version 1.0.4` 输出 |

**解说词**：「一条命令，所有 DUT 同时执行。以前工程师开 4 个 Putty 窗口复制粘贴，现在一条广播搞定。」

### 步骤 2.4 广播到部分

| 动作 | 预期结果 |
|---|---|
| 在广播栏第一行，**点一下 `dut-1` 的 chip**（取消选中，只剩 `dut-2` 亮） | chip 变暗 |
| 输入框敲：`show ip interface brief` 然后发送 | **只有 dut-2 窗格**回显命令和接口表；dut-1 无变化 |

**解说词**：「想只对某几台操作时，取消勾选其他就行。」

## 三、第三幕：Agent 闭环 —— 10 分钟 ⭐ 核心

### 步骤 3.1 切回聊天区

| 动作 | 预期结果 |
|---|---|
| 鼠标点到左侧**聊天输入框**（DSH 的主对话区） | 输入框获焦，可以打字 |

**解说词**：「现在开始展示核心价值——让 Agent 来操作环境。」

### 步骤 3.2 Agent 单机任务（读本地 + 操作设备）

| 动作 | 预期结果 |
|---|---|
| 聊天输入框敲：`读一下当前目录的 test-plan.md，按照里面的验证清单对 127.0.0.1:2323 这台设备执行` | DSH 开始思考 |
| **观察**：Agent 的回复 + 工具调用过程 | Agent 依次：①读本地 `test-plan.md`（工具调用可见）；②调 `tm_connect` 连设备（或复用已开的 dut-1）；③调 `tm_send` 跑 `show version`；④调 `tm_send` 跑 `show ip interface brief`；⑤调 `tm_send` 跑 `ping 8.8.8.8`；⑥汇总报告 |
| **同时观察**：右侧终端工作区 | Agent 连的会话对应的终端窗格里，能看到命令在被执行（人机共视） |
| Agent 回复出来 | 结构化报告：每条验证项 ✅/❌ |

**解说词**（在 Agent 跑的时候说）：「注意看右侧终端——Agent 在操作设备时，终端同步显示，不是黑盒。左边是 Agent 的分析，右边是设备的真实响应，两相对照。」

**如果 Agent 没调工具**：追加提示「请用 dsh-terminal-manager 提供的工具来操作设备」。

### 步骤 3.3 Agent 批量任务（对比两台 DUT）

| 动作 | 预期结果 |
|---|---|
| 聊天输入框敲：`把 2323 和 2324 两台 DUT 都跑一遍 show version，对比它们的固件版本是不是一致的` | DSH 开始思考 |
| 观察 Agent 行为 | Agent 调 `tm_send` 或 `tm_send_all`，拿到两台输出 |
| 同时观察终端工作区 | 两台窗格都有输出在滚动 |
| Agent 回复 | 给出对比结论，例如「两台都是 MockOS 1.0.4，版本一致」 |

**解说词**：「以前人工对比两台设备的输出，要切窗口、肉眼扫；现在 Agent 自动做。」

### 步骤 3.4 Agent 读现场（"看"屏幕）

| 动作 | 预期结果 |
|---|---|
| 聊天输入框敲：`连上 127.0.0.1:2323，告诉我当前屏幕上显示什么？设备什么状态？` | DSH 思考 |
| Agent 行为 | 调 `tm_read` 读当前环形缓冲 |
| Agent 回复 | 描述横幅（Mock Router）、当前提示符状态（空闲等待命令）等 |

**解说词**：「Agent 不只是发命令，它也能'看'屏幕。可以帮你确认设备是不是卡在某个状态、有没有异常输出。比如你可以问'设备现在是不是在 Rommon 模式'。」

## 四、第四幕：安全护栏 —— 3 分钟

### 步骤 4.1 演示命令守卫拦截

| 动作 | 预期结果 |
|---|---|
| 聊天输入框敲：`连上 127.0.0.1:2323，执行 rm -rf /` | DSH 思考 |
| Agent 调 `tm_send` | 工具返回 `COMMAND_BLOCKED` 错误 |
| Agent 回复 | 「该命令被安全策略拦截」 |
| **同时观察**：终端窗格 | 终端里**没有** `rm -rf /` 的回显（命令根本没到设备） |

**解说词**：「AI 路径的危险命令会被拦截——`rm -rf /`、`format`、`write erase` 这类都在黑名单里。但注意——」

### 步骤 4.2 演示人不被拦

| 动作 | 预期结果 |
|---|---|
| **点一下** dut-1 的终端窗格获得焦点 | 光标出现 |
| 键盘敲：`rm -rf /` 回车 | 终端直接回显 `unknown command`（模拟设备不识别），但**没有**被拦截 |

**解说词**：「人手敲的命令不被拦——因为人知道自己在干什么。安全策略只约束 AI，不干扰工程师。」

### 步骤 4.3 演示设备掉线保留现场

| 动作 | 预期结果 |
|---|---|
| 在 dut-2 的终端窗格里敲：`exit` 回车 | 模拟设备主动断开连接 |
| 观察终端窗格 | 窗格变灰（标记 `closed` 状态），但**历史输出保留**（横幅、之前的命令都还在） |
| 观察顶部「在线 X/Y」 | 变成「在线 1/2」（1 台在线、1 台已断） |

**解说词**：「设备掉了不丢现场。工程师可以回头看刚才的输出、复制日志。想重连的话——」

| 动作 | 预期结果 |
|---|---|
| 在「活跃会话」列表里找到 dut-2，**右键** → 重连（或点窗格上的重连按钮） | 窗格恢复活跃，重新出现 `router>` 提示符 |

## 五、收尾 + Q&A —— 5 分钟

### 步骤 5.1 关闭工作区

| 动作 | 预期结果 |
|---|---|
| 点终端工作区右上角的 **「✕ 关闭」** 按钮（或再次点侧边栏「🖥️ 终端管理」） | 工作区收起，聊天区恢复全宽 |
| 再点一次「🖥️ 终端管理」 | 工作区重新出现，之前连的会话还在（只要设备没断） |

### 步骤 5.2 Q&A 准备

预判的提问 + 应答：

| 问题 | 回答 |
|---|---|
| 能连真实设备吗？ | SSH（密码 + 密钥两种认证）和 Telnet 都支持；今天用模拟设备只是为了演示不依赖真实硬件 |
| 能存多少连接？ | JSON 本地持久化，数量没硬上限 |
| 广播能发多少台？ | 实测 10 台并发下延迟 < 100ms（本机回环）；受限于设备本身的处理能力 |
| Agent 能看到实时屏幕吗？ | `tm_read` 读环形缓冲（1MiB 上限），能看最近的全部输出；实时流通过 Terminal 面板看 |
| 人在终端敲的命令 Agent 能看到吗？ | 能——人机共享同一个环形缓冲 |
| 会话数据存在哪里？ | 本机内存 + 环形缓冲；DSH 进程在就在，进程退就清空 |
| 安全吗？ | 数据面 WebSocket 只接受 loopback（127.0.0.1）；控制面 `/term-manager` 本机绑定；AI 路径有命令守卫；错误消息永不含密码 |
| 凭据怎么存的？ | 本地 JSON，权限 0600（Windows 尽力）；后续接 DSH 的 `ctx.credentials` 加密存储 |
| 9 月还有什么？ | 缓存优化、开发环境集成、端口共享、记忆插件、芯片知识库导入（排期待定） |
| 能接我手头的真实板子吗？ | 可以——只要板子支持 SSH 或 Telnet，建连接填 IP/端口就能用；有问题我们一起联调 |

## 六、应急预案

| 问题 | 处理 |
|---|---|
| 模拟设备起不来（端口被占） | 换端口：`node scripts/mock-device.mjs 2325`，演示时表单填 2325 |
| 浏览器加载不出工作区 | 硬刷新 `Ctrl+F5`；或 F12 → Network → 看 `client.js` 是否 200 |
| Agent 不调用 `tm_*` 工具 | 在聊天里显式提示「请用 dsh-terminal-manager 的工具」；或重新描述需求 |
| 终端窗格黑屏 | 点一下窗格获得焦点；或 F12 看 WS 是否连上 |
| 广播没响应 | 检查「全部」chip 是否选中；检查目标会话是否在线 |
| 演示时间不够 | 砍第四幕（安全护栏），口头说「AI 路径有命令守卫，人不拦」一句话带过 |
| 演示过程中 mock-device 崩了 | 立刻在原窗口重新启动（同端口）；已有会话会标 `closed`，可重连 |

## 八、演示前的彩排建议

**至少完整跑一遍**（30 分钟）：
1. 起两台 mock-device
2. 起 DSH
3. 浏览器走完第一到第四幕
4. 重点确认：
   - Agent 能正确读到 `test-plan.md`（路径对）
   - Agent 会主动调 `tm_*` 工具（不要等太久）
   - 广播栏真的能同时发两条
   - `rm -rf /` 真的被拦了

如果 Agent 行为不稳，可以提前在聊天里给一句话定调：「接下来请你用 dsh-terminal-manager 工具完成任务」。
