# DSH Terminal Manager — 终端管理插件

## 问题

今天管理多台设备/环境的终端依赖传统终端工具：逐个开窗口、逐个敲命令、逐个看输出，存在两个断点：

1. **批量操作与多屏观察困难**：无法一次向多台设备广播指令，无法在一个界面同时观察多个会话的实时输出。
2. **Agent 断层**：DSH 的 Agent 无法操作这些外部终端——想让 Agent 跑一个测试命令，得人工复制粘贴到终端、再把输出搬回给 Agent。「Agent → 设备终端」这条链路是断的。

## 期望结果

MVP 验收画面（可观察、可演示）：

1. 在 GUI 中手动配置 IP、端口、协议（SSH / Telnet），点击连接即弹出对应终端窗口。
2. 同时保持并**实时展示**多个会话（规模 < 10）的输出。
3. 能向**指定会话**发送指令，也能**广播到全部会话**。
4. DSH Agent 通过插件暴露的工具 API 向指定会话发送测试命令、读取输出、回传结果。
5. 纯本地运行，不依赖 MCP 等外部中间件。

## 受影响的用户与系统

- **用户**：本人/小团队自用，日常设备测试与管理。并发连接规模小（< 10）。
- **系统**：DeepSeek Harness（DSH）框架。以**独立插件仓库**（dsh-plugin 生态惯例）扩展，不改 DSH 核心：
  - `ctx.terminals`（TerminalSessionService）：注册 `ssh` / `telnet` 新 backend 类型；
  - `ctx.tools`：注册面向 Agent 的工具（连接管理、发送指令、读取输出）；
  - Web UI（`ctx.slots`）：新增终端管理工作区（多终端面板、连接配置界面）。
- **决策人**：作者本人（产品负责人）。

## 约束

- 必须遵循 DSH 插件架构（Cordis，「一切皆插件」），只做挂载扩展，不 patch 核心。
- DSH 处于开发者预览阶段、快速迭代且将有破坏性变更，插件需容忍框架升级。
- **纯本地部署**：插件运行于本机 DSH host 进程，连接由本机直连目标设备，不引入任何外部中间件。
- 技术栈跟随 DSH：TypeScript / React 18 + CSS Modules，插件为「host 半 + 浏览器半」双半包结构。

## 范围外（MVP 明确不做）

- 串口（Serial）连接。
- 文件传输（SFTP / SCP）。
- 从设备拉取/管理日志文件。
- 多用户协作、云端或远程部署。
- 命令录屏、审计回放等合规功能。

## 开放问题

1. 「日志」确认：MVP 按**各会话实时输出流**（同屏多窗格展示）理解，是否正确？
2. SSH 认证方式：MVP 支持密码、密钥还是两者都要？
3. Telnet：需要标准协议协商，还是裸 TCP 即可？
4. GUI 形态：嵌入 DSH Web UI 的面板/工作区，还是独立窗口？外观有无参考对象（如某个喜欢的终端工具）？
5. 设备连接信息（IP/端口/凭据）如何存储与保护？是否需要加密？
6. Agent 读输出的完成判定：读当前缓冲区，还是等待命令执行完成（输出结束符/提示符检测）后整段返回？
